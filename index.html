01 · ROLE & STRATEGY

这个角色的核心，不是催进度

它需要把“模型需要什么”翻译成“团队如何稳定生产”，并用独立评测证明每批数据是否真的产生增益。

01
⌁

数据策略

从能力缺口出发，定义任务分层、数据来源、难度结构与训练信号。

  • 真实任务锚定分布
  • 合成数据放大规模
  • Bad Case补充长尾
02
⬡

环境工厂

让仓库、依赖、工具、权限和初始状态可以冻结、拉起、回放与销毁。

  • 环境 ID 与快照
  • 健康检查与失败分层
  • 轨迹记录与重放
03
✓

质量门禁

用结构化 Reason Code 和独立验证器替代“看起来不错”的主观判断。

  • Schema → 执行 → 语义
  • 人工抽检与争议仲裁
  • 安全与污染隔离
04
↻

评测飞轮

建立通用回归与专项能力双层 Benchmark，连接数据、训练和线上反馈。

  • 基座/历史/当前对照
  • 训练前后同切片评测
  • 退化定位与快速回滚

03 · BAD CASE WORKBENCH

从经验判断，升级为可复验的因果证据

用状态机、控制变量实验和证据门禁，让工程、算法、数据与评测在同一套事实基础上协作。

REAL CASE · ABSTRACTED

相同触发条件导致
步骤节点混淆

04 · 30 / 60 / 90 DAYS

先跑通，再产品化，最后规模化

不追求一次性重建全部平台，而是用一个高价值 Coding 场景形成最小闭环，再沉淀可复制的标准、工具与机制。

DAY 01—30基线与共同语言

选择正确的问题

完成链路盘点、数据契约、质量基线和试点选择。

  • 利益相关方与现状流程图
  • Case Schema / Taxonomy / RACI
  • 数据批次质量基线
  • P1 Case 与 Coding 试点
OUTCOME 可信基线 + 60 天验收口径
DAY 31—60最小可行闭环

证明链路能工作

跑通环境、生成、质检、交付和专项评测。

  • 环境工厂 MVP 与稳定回放
  • Validator 插件与 Reason Code
  • 首个训练数据批次
  • 双层 Benchmark 与版本对照
OUTCOME 可执行、可验证的数据流水线

  • Neo / Agent 真实任务切片
OUTCOME V1.0 管线 + 下一季度 Roadmap
05 · SUCCESS METRICS

不以数据量作为唯一答案

指标应在前两周基于现状校准；首版建议同时衡量质量、效率、可追溯性和模型边际增益。

THE STATE AFTER 90 DAYS

让每一批数据都能回答
“为什么做、如何证明、带来什么改变”

能力假设与优先级明确

如何证明它是好数据？
环境可复现、Verifier 独立

快速定位、修复、回归与回滚

TPM 的价值，是让决策有证据、交付可复现、问题可追溯，并使专家把时间投入真正需要专业判断的地方。
