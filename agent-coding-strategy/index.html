01 · 2023—2024

当时的主要矛盾：基础代码能力与覆盖不足

函数级和相对独立的问题占主导，数据生成和验证成本较低。按语言、题型和难度补齐弱项，在当时是合理且高效的策略。

PRETRAIN

扩大代码知识覆盖

高质量仓库、技术文档、Issue与问答，兼顾项目级上下文。

  • 语言/领域/仓库质量分层
  • 去重、许可证与污染治理
  • FIM / FIB 数据构造
SFT

对准明确任务弱项

生成、补全、纠错、解释和测试等可清晰标注任务。

  • 语言与任务类型切片
  • 可执行和单测正确
  • 专项短板定向补数
PREFERENCE

学习方案与风格偏好

同题多候选，通过执行结果与人工开发品位构造排序。

  • 正负差异可归因
  • 避免低级噪声负例
  • 正确性与可维护性兼顾
EVAL

函数级正确率为主

HumanEval/MBPP/MultiPL-E 类评测叠加内部语言切片。

  • Pass@k / 编译率
  • 单测通过率
  • 语言和题型覆盖
02 · STEP AGENT STAGE

当前的主要矛盾：长链任务的稳定性与可验证性

阶跃公开模型已把 Coding 与 Agent 放在同一能力框架：长上下文、终端任务、工具调用、编排和生产级稳定性成为显性目标。以下策略是基于公开信号形成的候选人推演，不代表内部路线。

Task + Environment + Context + Trajectory + Verifier + Outcome

Agentic & Verifiable

OBJECT 02EnvironmentCommit、依赖、终端、权限
OBJECT 03Context文件、检索、历史与记忆
OBJECT 04Trajectory计划、工具、错误与恢复

03 · DATA PORTFOLIO

不先拍固定配比，先定义每类数据解决什么问题

配比是能力缺口、样本有效率、训练边际收益和成本的函数。先建立能力矩阵，再通过小规模训练与消融逐轮调整。

数据来源主要价值准入与风险控制
真实仓库 / Issue真实工程分布、跨文件修改与经济价值许可证、时间切分、环境可复现
自动合成任务扩大语言、难度和能力切片覆盖模板化、同源偏差、独立Verifier
成功轨迹学习工具使用、规划与有效恢复偶然成功、冗长轨迹、奖励投机
失败轨迹学习错误识别、偏好边界与恢复策略失败节点、可归因性、可修复性
真实 Agent Case产品分布、长链任务和安全约束脱敏、权限、状态追踪与回滚
04 · TRAINING SIGNAL

不同问题，进入不同训练出口

不能把所有Bad Case都转成SFT数据。先判断缺陷属于知识、行为偏好、长链决策还是工程层，再选择训练或工程方案。

SFT

学习高质量示范

适合清晰、稳定、可复现的正确轨迹和工具使用范式。

  • 保留关键决策与恢复
  • 过滤偶然成功与无效循环
  • 控制风格和轨迹长度
DPO

学习可归因偏好

适合同任务下方案、工具或轨迹质量具有明确差异的样本。

  • 正负差异单一清晰
  • 兼顾正确、成本与安全
  • 避免模型同源偏差
RLVR

优化长链任务完成

适合环境可复现、奖励可验证、探索空间较大的任务。

  • 确定性Reward优先
  • 难度课程与通过率带宽
  • 防止奖励投机
ENGINEERING

不该训练的问题

环境、路由、权限和工具Schema缺陷优先在系统层止损。

  • Prompt / Tool / Router修复
  • 重试、超时与回滚
  • 修复后仍进入回归集
05 · 90-DAY EXPERIMENTS

我的第一版实验，不从“大规模生产”开始

选择一个具有确定性Verifier的仓库级或终端任务，以小样本验证数据对象、生成方式和训练信号是否有效。

DAY 01—30

能力与数据基线

建立任务、难度、失败和数据来源矩阵。

  • 审计2—3个代表性批次
  • 建立六对象数据契约
  • 冻结通用与专项评测切片
产物：能力矩阵 + Dataset Card V0.1
DAY 31—60

最小数据实验

用真实锚点、合成任务和成功/失败轨迹组成小规模实验组。

  • 环境与Verifier准入门禁
  • 基座/历史/当前版本对照
  • 来源、难度与轨迹消融
产物：首批数据 + Benchmark V0.1
DAY 61—90

决定是否扩量

以边际模型增益和单位有效数据成本决定下一轮策略。

  • 专项切片获得正向信号
  • 通用回归无显著退化
  • 形成继续/调整/停止建议
产物：策略复盘 + 下一季度Roadmap
